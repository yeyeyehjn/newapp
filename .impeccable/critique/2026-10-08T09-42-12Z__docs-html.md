## Design Specificity Verdict

**判定：为本案专门撰写（约 85% 专属），不是可套用的通用模板。**

LLM 评估：专属证据链完整且互相咬合——顶栏「穗仲云 · 仲裁员端 · 共 8 模块」+ 机构 logo；目录八节即产品真实办案动线（登录 → 首页 → 案件 → 待办 → 签署/延期 → 统计 → 我的）；章节限定语带真实业务边界（「五个详情标签」「声明承诺书 / 笔录 / 结案文书 / 草拟裁决」「同意 / 驳回」）；最有力的是**图注语义色与截图内状态徽章一一对应**（`.kw` 去签名 = 待签，`.ks` 驳回 = 红，`.ko` 同意 = 绿，`.ka` 庭审笔录/电子卷宗/审批流转记录 = 材料对象），颜色在承载业务含义而非装饰。通用件只有顶栏、step 徽章、页脚，占比很低。真正的失分不在"通用"，而在"没做全"——见 Priority Issue 1。

确定性扫描：`impeccable detect --json` 退出码 2，**14 条 findings**：

- `undersized-ui-text` ×6 —— 指向概览区 6 个胶囊（源码 L236–241，10px）。**一半是有效发现**：在 1180px 桌面画布上，10px 胶囊确实偏小；但它同时是 DESIGN.md §1.2.2 明文规定的「标签」档，属规范内选择，不是失控值。**一半是漏报**：同文件 10px 的 `.step` 步骤徽章（L177/179）与 10px 页脚（L191）它没抓到。
- `numbered-section-labels` ×8 —— 指向 `.sec-num` 01–08。**判定为误报（false positive）**：本条规则的默认前提是「序号无信息量」，而这份指引是编号动线（登录→首页→案件→待办→签署→统计→我的），**顺序本身就是它要传达的信息**，且与目录 `.idx` 互为索引。序号应当保留。

检测器整体为漏报下限：`--scope layout` 返回 `[]` 不代表合格，`--scope color` / `--scope a11y` 并非合法 scope（引擎只支持 `type|layout`），因此**对比度与无障碍没有任何自动检查**，本报告的这两项全部由手工计算/逐行核验得出。

## Overall Impression

一份**克制、专业、基本可信**的机构手册：信息层级干净，图注颜色系统是真正的亮点，锚点跳转的 `scroll-margin-top:86px` 这类细节有人想过。最大的机会不在视觉，而在**结构与文案的「最后一公里」**：它告诉你"点哪里"，但很少告诉你"点完算成功""这一步不可撤回""这一步为什么必须这么做"。对一份要指导仲裁员完成签署、审批这类终局性动作的手册来说，这是最该补的一块。最大的单点风险则是移动端——目录一滚走，8 节长页面就变成了没有地图的荒地。

## What's Working

1. **图注语义色 = 状态色映射**。`.kw/.ks/.ko/.ka` 不是配色，是把截图里徽章的颜色语义搬到文字上（待签 / 驳回 / 同意 / 材料对象）。读者看一眼图注就能把颜色与业务状态挂钩，这是通用手册做不到的。
2. **`.sec-head` 三件套**：编号徽章 + h2 + 右侧 `.sec-tip` 给「号 / 名 / 范围」，一眼定位；且 §08 删掉一张图后编号仍连续 1–5，说明编号是手写维护过的、不是自动序号。
3. **锚点跳转被 sticky 顶栏遮挡的问题被提前解决**（`scroll-margin-top:86px`，L135），且 8/8 锚点全部命中对应 `id`，无断链。

## Priority Issues

### [P1] 覆盖缺口：酬金、聘书、合议讨论三块能力未进指引
**What**：目录只有 8 节，产品已实现的酬金单、我的聘书、案件合议讨论没有对应章节。磁盘上 `29-remuneration.png`、`35-login-face-step2.png` 从未被引用；`37-appointment.png` 只存在于 L455–458 被注释掉的整段 `<figure>` 里。
**Why it matters**：仲裁员在工作台点进「酬金」或「我的聘书」后，手册里没有下一步，读者会认为自己漏读了某章。同时 §01 人脸识别只讲到「验证码」就跳走了，真取景界面 `35-login-face-step2.png` 明明存在却没用——登录是全文第一步，第一步就断线最伤信任。这是详细程度上的 P1，不是 P0：已覆盖的流程仍可完成。
**Fix**：新增 `section#s9`（酬金）与 `#s10`（我的聘书 / 合议），同步补目录条目；把 `35-login-face-step2.png` 插入 §01 作为 step 3，后续步骤顺延；删除或恢复 L455–458 的注释块，不要留悬空引用。
**Suggested command**: `/impeccable shape`

### [P1] §03 / §05 长网格过载，决策点选项远超 4 个
**What**：§03 一屏 7 张截图、§05 一屏 8 张，全部平铺无分组、无折叠。对应认知负荷 checklist 的三项失败：一次一件事、最少选项（单一决策点 >4 个可见选项）、渐进披露。
**Why it matters**：读者在 §05 面对「声明承诺书 / 笔录 / 结案文书 / 草拟裁决」四个性质完全不同的流程，却被混在同一个八宫格里，只能靠逐张读图注来分辨。工作记忆装不下，结果是跳过。
**Fix**：在 §05 内按四类流程插入 `h3` 小节（声明承诺书 3 图 / 笔录 2 图 / 文书 1 图 / 草拟裁决 1 图），§03 按「列表 → 详情五个标签 → 卷宗」拆两段；或对次要图组用 `<details>` 折叠并同步 `aria-expanded`。
**Suggested command**: `/impeccable layout`

### [P1] 移动端导航整体失效
**What**：`@media (max-width:860px)` 把 `.toc` 从 `position:sticky` 改为 `static`（L184 起）。目录一旦滚出视口，这份 8 节长页面就没有任何导航，也没有回顶入口。
**Why it matters**：产品最终形态是**微信小程序**，参照 PRODUCT.md，读者几乎一定是在手机上打开这份指引。桌面原型上无感的缺陷，在真实使用场景里是主路径缺陷。这正是 Casey（手机分心用户）会直接放弃的地方。
**Fix**：<861px 时把目录改为顶部横向滚动的 sticky 胶囊条（`overflow-x:auto` + `scroll-snap`），并在每节末尾加「↑ 返回目录」返回 `#top`；给 `#top` 锚点补 `id`。
**Suggested command**: `/impeccable adapt`

### [P2] 高风险动作缺安全感文案，图注缺「完成判定」
**What**：§05 签署、§06 驳回是全篇风险最高的两个动作，但只写了点哪里。§06 step 4 的「二次确认 → 自动通知办案秘书」是全文唯一一处安全感设计，§05 则完全没有说明签署的终局性。多数图注以「核对 XXX」「查看 XXX」收尾，没有成功标志。
**Why it matters**：仲裁员的签署与驳回是法律行为。手册若不说明「提交后不可撤回」，读者要么不敢点，要么点了才发现无法回退——两种都伤机构信任。
**Fix**：在 §05 / §06 章节顶部加一条 `.callout`（`bg-error-bg` 底 + `--color-error` 字）写明「签署即终局，提交后不可撤回」；把各节 `.sec-tip` 从范围描述改写为成功标志（如 §06 写「提交后待办消失、秘书收到通知」）。
**Suggested command**: `/impeccable clarify`

### [P2] 标记层硬缺陷批次（由 Assessment B 逐行核出）
**What**：37 张 `<img>` **全部**缺 `width`/`height`、**全部**缺 `loading="lazy"`（首屏下方几十张截图全量加载 → CLS 抖动 + 浪费流量）；全文件无 `prefers-reduced-motion` 处理；10 处间距非 4px 倍数（L57/81/88/93/105/116/119/132/135/141 等，偏离 DESIGN.md §1.3）；5 个 `:root` 变量定义后从未使用（`--brand-accent`、`--info`、`--status-active`、`--status-pending`、`--status-signing`）；`.kw/.ks/.ko` 用裸十六进制色（L184–186）而非 Token；`.mono` 类（L40）全文件未被使用。
**Why it matters**：图片无尺寸是唯一一个会被读者直接感知的性能缺陷（滚动时页面跳动）；本机微信 WebView 多为中低端安卓，几十张全量加载的代价比桌面预览大得多。未使用变量与裸色值会让后续改版时「改了变量却没生效」，是维护陷阱。
**Fix**：为每张 `<img>` 补 `width`/`height`（按截图真实像素比例）与首屏以下 `loading="lazy"`；把三种图注语义色提升为 `:root` 变量（并说明它们不在 DESIGN.md Token 内，属本文件的补充色）；删掉未使用的 5 个变量与 `.mono` 类，或补齐使用。
**Suggested command**: `/impeccable audit`
